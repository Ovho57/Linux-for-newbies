# Contributing

Thanks for helping make these lessons clearer and more useful.

## What makes a good contribution?
- Explain the reason behind a command, not only its syntax.
- Use commands that work on a named distribution/version where possible.
- Include expected output or explain what may vary.
- Add a small exercise and mention common mistakes.
- Link to official documentation for details.
- Keep beginner lessons welcoming and avoid unexplained jargon.

## Safety and accuracy
- Never include passwords, private keys, tokens, or personal data.
- Clearly label commands that modify system state.
- Do not recommend destructive commands without a safe explanation and recovery considerations.
- Security material must focus on systems you own or are authorized to administer.
- Test commands in a disposable VM or container before submitting.

## Suggested lesson structure
1. What you'll learn
2. Why it matters
3. Concepts explained
4. Examples
5. Common mistakes
6. Exercises
7. Further reading

Keep changes focused. If you spot an error, open an issue or submit a pull request with the correction.
